# エージェント間連携プロトコル

## 基本原則

1. **司令塔（CLAUDE.md）は作業しない**。判断と委任とまとめのみ
2. **producer と reviewer は別エージェント**で独立起動
3. **複合タスクは並列起動**（同一メッセージ内で複数 Agent tool 呼び出し）
4. **依存があるタスクは順次**（producer → reviewer は順次）

## 委任時の引き継ぎフォーマット

司令塔から部門エージェントへの依頼テンプレート：

```
## 依頼背景
（川辺の要望そのまま、または要約）

## 対象事業 / 媒体 / ターゲット
（明示）

## 期待する成果物
（テンプレ名 or 形式）

## 制約・留意点
（締切・予算・公開可否 等）

## 関連情報
- 過去の関連投稿:
- 参照ファイル:
```

## producer → reviewer 引き継ぎ

```
## レビュー依頼

## 成果物
（producer 出力をそのまま）

## producer 自己チェック結果
- [ ] ターゲット明示
- [ ] 根拠あり
- [ ] 禁止事項なし
- [ ] テンプレ準拠

## 特に見て欲しい点
- ...
```

## reviewer → producer 差し戻し

reviewer の出力フォーマット（共通）：

```
## 評価: PASS / NEEDS_REVISION / REJECT
## 修正必須: ...
## 修正推奨: ...
## 総評: ...
```

producer は NEEDS_REVISION を受けたら、修正版＋「修正対応サマリ」を
返す。reviewer に再提出。

## 並列起動のパターン

### パターンA: 複数事業同時
- 例: 全事業の月次レポート
- finance-ops に4事業分まとめて依頼（1エージェントで通す方が整合性が高い）

### パターンB: 多媒体・多領域
- 例: LaTokyo新メニュー設計＋告知投稿＋クーポン文
- `latokyo-marketer`（メニュー＋クーポン）と `content-writer`（SNS告知）を並列
- 双方完了後、各 reviewer に通す

### パターンC: 戦略＋実行
- 例: 「来月どう動こう」
- `strategy-planner`（戦略案）と `finance-ops`（数値）を並列
- 戦略案ができたら関連する実行系エージェントへ

## 競合・重複の解消

- 司令塔は同じ案件を複数 producer に渡さない
- producer 間で意見が割れる場合は司令塔が統合判断
- 統合できない場合は川辺確認

## 終結条件

- reviewer が PASS を出した時点で完了
- NEEDS_REVISION 3周目に入る前に司令塔経由で川辺確認
- REJECT は即川辺確認（要件齟齬の可能性が高い）

## ログ

各エージェントは出力の最後に「次アクション」を1〜2行添える：

```
## 次アクション
- 司令塔へ: 〇〇のレビュー依頼
- 川辺確認推奨: 公開タイミング
```
