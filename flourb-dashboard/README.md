# Flourb 売上 × 広告 統合ダッシュボード（GAS）

Flourb（名古屋の美容サロン）の売上3シートと Meta 広告費を1枚に集約する、
Google Apps Script (GAS) 製の統合ダッシュボードです。

- 既存の3つの売上シートは **読み取り専用**（絶対に書き換えません）
- 新しいダッシュボード用スプレッドシートに月別で集計を書き出します
- 毎日1回、自動更新されます

---

## 何ができるか

「ダッシュボード」タブに、1行1ヶ月で以下が並びます。

| 月 | 本体売上 | 蘭ちゃん売上 | みやちゃん売上 | 売上合計 | 新規数 | Meta新規数 | Meta売上 | 広告費 | CPA | ROAS |
|----|---------|------------|--------------|---------|-------|-----------|---------|-------|-----|------|

- **Meta売上** = 蘭＋みやの実額（顧客ルート「Meta広告」の料金合計）＋ 本体の概算（本体Meta新規件数 × 客単価）。
  - 実額と概算の内訳は、各 Meta売上セルの **メモ（コメント）** に表示されます。
  - 本体は売上と経路が紐づかないため、本体分は概算です（正確化したい場合は後述）。
- **CPA** = 広告費 ÷ Meta新規数（合計）
- **ROAS** = Meta売上 ÷ 広告費
- ゼロ割りは `-` で表示します。

## ファイル構成

| ファイル | 役割 |
|---------|------|
| `appsscript.json` | マニフェスト（タイムゾーン Asia/Tokyo） |
| `Config.gs` | スプレッドシートID・広告アカウント・プロパティ名・ルート一覧 |
| `Util.gs` | 金額パース（日付除外）・ルート正規化・月キー検出・行列探索 |
| `ParseHonten.gs` | 本体「ハーブピーリング2026」パーサ（日報グリッド型） |
| `ParseMeisai.gs` | 蘭ちゃん・みやちゃん共通パーサ（明細型） |
| `MetaAds.gs` | Meta Marketing API で月別 spend を取得 |
| `Dashboard.gs` | ダッシュボードへ書き出し（新規SS自動作成・ID保存） |
| `Dropdowns.gs` | 顧客ルート列にプルダウンを設定（`setDropdowns`） |
| `Main.gs` | `updateDashboard` / `installDailyTrigger` / メニュー |

### 主な関数

- `updateDashboard()` … 全ソース集計 → Meta広告費取得 → ダッシュボード書き出し
- `setDropdowns()` … 蘭・みやの「顧客ルート」列にプルダウンを設定（既存値は保持）
- `installDailyTrigger()` … 毎朝6時台に `updateDashboard` を回すトリガーを設置（重複排除）
- `setMetaToken('トークン文字列')` … アクセストークンをスクリプトプロパティに保存

## セットアップ

### 方法A: clasp を使う（推奨）

```bash
npm i -g @google/clasp
clasp login

# このフォルダで新規プロジェクトを作る場合
cd flourb-dashboard
clasp create --type standalone --title "Flourb 統合ダッシュボード" --rootDir .
#  → .clasp.json が生成されます（scriptId が入ります）

clasp push
```

すでに Apps Script プロジェクトがある場合は、`.clasp.json.example` をコピーして
`.clasp.json` を作り、`scriptId` を自分のものに書き換えてから `clasp push` してください。

```bash
cp .clasp.json.example .clasp.json
# .clasp.json の scriptId を編集
clasp push
```

### 方法B: Apps Script エディタに貼る

clasp を使わない場合は、`*.gs` ファイルの中身をそのまま Apps Script エディタに
コピペし、`appsscript.json`（マニフェスト）も一致させてください。

## Meta アクセストークンの入れ方

トークンは **コードに直書きしません**。スクリプトプロパティで管理します。
（Meta のビジネス設定でシステムユーザートークンを発行。`ads_read` 権限が必要）

いずれかの方法で `META_ACCESS_TOKEN` を設定してください。

- **エディタから**: 関数 `setMetaToken` を開き、一時的に引数を渡して実行する。
  または Apps Script の「プロジェクトの設定 → スクリプト プロパティ」で
  プロパティ名 `META_ACCESS_TOKEN`、値にトークンを追加。
- **未設定でもOK**: トークンが無い場合、広告費・CPA・ROAS は `-`（空欄）になり、
  売上や新規数などは通常どおり集計されます（エラーで止まりません）。

## 実行手順

1. まず `setDropdowns()` を1回実行 → 蘭・みやの顧客ルート列にプルダウンが入る。
2. `updateDashboard()` を1回実行 → ダッシュボードが新規作成され、集計が書き出される。
   - 初回はダッシュボード用スプレッドシートが自動生成され、その ID が
     スクリプトプロパティ `DASHBOARD_SPREADSHEET_ID` に保存されます。
   - 実行ログ（表示 → ログ）に作成された **スプレッドシートのURL** が出ます。
3. 結果を確認し、パース結果が実データとズレていたら調整（後述）。
4. 問題なければ `installDailyTrigger()` を実行 → 毎日自動更新が有効化。

### トリガーの確認

Apps Script エディタ左メニューの「トリガー（時計アイコン）」で、
`updateDashboard` の「日タイマー / 午前6〜7時」トリガーが1つあることを確認します。
`installDailyTrigger()` は毎回、既存の同名トリガーを削除してから作るので重複しません。

## パースの考え方（要調整ポイント）

3シートは形式がバラバラで、列ズレ・表記ゆれ・混在が多いため、
**列位置を決め打ちせず、見出しで探し、行を丸ごと走査**しています。

### 本体（日報グリッド型）
- 各月タブの1行目から「合計」列を検出。
- A列の見出しで行を特定：
  - `売上` で始まる最初の行（実データは `売上　　10階`）→ 本体売上
  - `新規客数` 行 → 新規数
  - `meta` 行 → Meta新規“件数”
- 客単価 = 本体売上 ÷ 新規客数（本体Meta売上の概算に使用）。

### 蘭ちゃん・みやちゃん（明細型）
- `施術日` と `顧客ルート` を含む行をヘッダーとして検出し、次のヘッダーまでを明細として集計。
- 月は「単独セルの月マーカー行（例 `2025/10`）」またはタブ名から判定。
- **料金** = 行の左から「最初にパースできる金額」。
  - 日付(`4/7`)や分数(`1/6`)は除外。手当・経費・振込合計は右側にあるため実料金が先に当たる。
  - 日付欠落で列が左にズレた行（料金がA列）にも対応。
- **顧客ルート** = 行内で最初に既知ルートへ正規化できるセル。
  表記ゆれ（`メタ`→Meta広告、`Theads`→Threads、`HPB`/`HP`→HotPepper、`友達`→知人 など）を吸収。
- **Meta売上/Meta新規数** = ルートが「Meta広告」に正規化された行の料金合計/件数。

### 調整方法
- パーサは `ParseHonten.gs` / `ParseMeisai.gs` にあります。
- 見出し文字が変わった場合は該当の判定（`normKey_` 比較）を調整。
- ルートの表記ゆれ追加は `Util.gs` の `normalizeRoute_` に条件を足す。
- 既知の限界：日付の打ち間違い（例 `1029` のようにスラッシュ無しの4桁）は
  金額として拾ってしまう可能性があります。元シート側の表記を直すのが確実です。
